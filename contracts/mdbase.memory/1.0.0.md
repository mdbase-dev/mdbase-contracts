# Memory

A record exposed through `mdbase.memory` holds one thing an assistant should
remember about the person it works for: who they are, how they want
assistants to work, what they are working on, or where to find something.
Several assistants, such as Claude, ChatGPT and Codex, read and write the same
memories, so what one learns the others can use.

The Markdown body is the memory itself. The contract's fields are the index an
assistant reads before deciding which bodies to open.

## Fields

- `name` identifies the memory: a short kebab-case slug such as
  `prefers-metric-units`. It is the memory's identity, never its path or file
  name. An implementing type may store it in the path.
- `description` is one line, specific enough that an assistant can tell from
  it alone whether the memory matters to the conversation at hand.
- `kind` is one of:
  - `user`: who the person is, such as their role, expertise or circumstances;
  - `feedback`: how they want assistants to work, including corrections and
    approaches they confirmed;
  - `project`: ongoing work, goals, decisions and dates not recorded elsewhere;
  - `reference`: where to find things, such as documents, dashboards or
    other collections.
- `by`, when present, names the assistant that saved or last changed the
  memory, such as `Claude`. It is a display hint, not an identity or
  authority.

## One memory per name

A collection should hold at most one memory per `name` across all types that
implement this contract. An application that finds several records with the
same name MUST report the duplicate and MUST NOT silently merge them or pick
one to change. Implementing types may declare `collection.unique` on their
name field so the engine reports duplicates within the type.

## Recalling

An assistant recalls by listing memories with only `name`, `description` and
`kind`, then reading the bodies of the few that matter to the conversation.
It does not read every body up front.

## Saving

Before saving, an assistant looks for an existing memory on the same subject
and updates it rather than adding another. One memory holds one subject. A
`feedback` or `project` body states the fact, then a line beginning `Why:` and
a line beginning `How to apply:`. Dates are written as absolute dates, never
as "yesterday" or "next week". Memories link to related memories as
`[[name]]`.

A memory never holds passwords, keys, tokens or other secrets.

## Forgetting

Forgetting a memory deletes its record. Applications that show memories to
the person should let them read, correct and forget each one.

This artifact is passive. Implementing it grants no authority to read, create,
or modify any record.
